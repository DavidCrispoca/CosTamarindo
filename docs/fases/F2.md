## 1. Objetivo

Que el juego se pueda jugar de principio a fin dentro del editor, sin red:
menú → partida → 3 vidas → game over → reintento, con puntaje y colección.

---

## 2. Qué quedó implementado

### 2.1 Scripts (`unity/Assets/Scripts/`)

| Archivo | Responsabilidad |
| :--- | :--- |
| `Core/GameState.cs` | Enumeraciones `GameState` / `ItemKind` y el modelo `ItemDef` |
| `Core/GameManager.cs` | Estado autoritativo local: vidas, puntaje, tiempo, eventos |
| `Core/CollectionBook.cs` | Ítems descubiertos en `PlayerPrefs` (solo presentación) |
| `Gameplay/ItemCatalog.cs` | Catálogo de 8 ítems con puntos, peso y multiplicador de caída |
| `Gameplay/ItemSpawner.cs` | Aparición, curva de dificultad, detección de captura y pooling |
| `Gameplay/FallingItem.cs` | Movimiento y rotación del ítem (lo impulsa el spawner) |
| `Gameplay/PlayerController.cs` | Movimiento horizontal: teclado, ratón y táctil |
| `Gameplay/PlaceholderSprites.cs` | Sprites de relleno generados en memoria |
| `UI/HudController.cs` | Puntaje, tiempo, corazones y récord |
| `UI/OverlayController.cs` | Pausa, game over, reinicio y enlace de botones |

### 2.2 Reglas del juego

| Elemento | Valor | Dónde |
| :--- | :--- | :--- |
| Vidas iniciales | 3 | `GameManager.startingLives` |
| Duración | 120 s | `GameManager.matchDurationSeconds` |
| Ítems buenos | +10 a +25 pts | `ItemCatalog` |
| Peligros (erizo, medusa) | −1 vida | `ItemCatalog` |
| Basura | −10 pts, sin vida | `ItemCatalog` |
| Dificultad | intervalo 0.95 s → 0.38 s; caída 3.6 → 7.5 u/s | `ItemSpawner` |
| Récord | `PlayerPrefs` (`ct.best_score`) | `GameManager` |

> El puntaje local **nunca** es el definitivo: en F5 el backend valida una firma
> HMAC y descarta envíos alterados (A.8.9 y A.8.24).

### 2.3 Escena

`unity/Assets/Scenes/Game.unity` (build index 0), generada por
`Assets/Editor/CosTamarindoSceneBuilder.cs` (menú **CosTamarindo → Construir escena de juego**):

```
Game
├── Main Camera      (ortográfica, size 5, fondo mar)
├── GameManager      (reglas + eventos)
├── Player           (SpriteRenderer + PlayerController)
├── Spawner          (ItemSpawner con los sprites de Assets/Art/Items)
├── UI               (Canvas 1920×1080, HudController, OverlayController)
│   ├── ScoreText · BestText · TimerText · LivesText · PauseButton
│   ├── PausePanel    (Continuar / Reiniciar)
│   └── GameOverPanel (puntaje, récord, desglose, Reintentar)
└── EventSystem      (InputSystemUIInputModule)
```

La escena es un archivo normal y editable; el generador solo se usa para
rearmarla desde cero de forma reproducible.

## 3. Herramientas y flujo de trabajo

| Necesidad | Herramienta | Nota |
| :--- | :--- | :--- |
| Compilar y detectar errores | `Unity.exe -batchmode -quit -executeMethod …` | Más fiable que el MCP para compilar |
| Corrección automática | `-runTests -testPlatform PlayMode` | Devuelve XML de resultados |
| Editar escena en vivo | Unity MCP (`manage_scene`, `manage_editor`, `execute_code`) | Recuperado tras fijar `MCPForUnity.AutoStartOnLoad` |
| Compilación en Unity | `CosTamarindo.asmdef` + `CosTamarindo.Tests.PlayMode.asmdef` | Separa runtime, tests y editor |

### 3.1 Hallazgos del entorno

1. **El puente MCP no arranca solo** si `EditorPrefs["MCPForUnity.AutoStartOnLoad"]`
   está en `false`. Se reactiva con `EditorBootstrap.EnableMcpAutoStart()` en batchmode
   (helper `Assets/Editor/EditorBootstrap.cs`).
2. **`execute_code` (CodeDom) no acepta `using`**: usar tipos calificados.
3. **El bucle de juego se congela sin foco**: se corrige con
   `Application.runInBackground = true` en `GameManager.Awake` (el ajuste de
   Player Settings no basta en el editor).
4. **Capturar pantalla del editor no es fiable** si la ventana no tiene foco:
   para verificar arte se renderiza la cámara a un `RenderTexture`.
5. **Unity tarda varios minutos** en reimportar la Library tras renombrar la
   carpeta del proyecto (cambian las rutas absolutas de los artefactos).

Los PNG originales del MCP venían **sin transparencia** (el badge crema quedaba
sobre blanco). Se resolvió renderizando los SVG de origen con
`tools/svg-render/` (`@resvg/resvg-js`, escala 3), que conserva el alfa.

`ItemSpawner.NormalizeScale` ajusta cada ítem a ~1.05 unidades: los assets de
Figma pueden llegar con cualquier tamaño en píxeles sin romper el gameplay.

## 6. Cómo ejecutarlo

```powershell
# Editor abierto en unity/ y escena Game cargada
# Play (▶) o:
& "C:\Program Files\Unity\Hub\Editor\6000.3.27f1\Editor\Unity.exe" `
  -batchmode -projectPath unity -runTests -testPlatform PlayMode `
  -testResults "$env:TEMP\playtests.xml" -logFile "$env:TEMP\playtests.log"
```

Controles: **A/D** o **←/→**, o arrastrar con ratón/dedo. **Esc/P** pausa.
