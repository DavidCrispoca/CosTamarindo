## 5. Decisiones y aprendizajes

### 5.1 Renombrar el proyecto Unity

`Move-Item CosTamarindo unity` falla con *«El proceso no puede obtener acceso al
archivo porque está siendo utilizado en otro proceso»* aunque el editor esté cerrado.

**Causa real:** el servidor `mcp-for-unity` (proceso Python lanzado por el puente del
editor) mantiene el directorio del proyecto como *current working directory*, y en
Windows eso bloquea el renombrado del directorio.

**Procedimiento correcto:**

1. Cerrar el editor (`CloseMainWindow()`; `manage_editor` no tiene acción *quit*).
2. Terminar los procesos `mcp-for-unity` y `unity.exe serve` del Hub.
3. `Rename-Item CosTamarindo unity`.
4. Relanzar `Unity.exe -projectPath …\unity`; el puente MCP se re-registra solo.

### 5.2 TMP Essentials

El elemento de menú `Window/TextMeshPro/Import TMP Essential Resources` responde
`success: true` pero **no importa nada**. El método que funciona es el API del editor:

```csharp
UnityEditor.AssetDatabase.ImportPackage(
    "Packages/com.unity.ugui/Package Resources/TMP Essential Resources.unitypackage",
    interactive: false);
```

### 5.3 `execute_code` del MCP

El compilador interno (CodeDom) **no acepta `using`**: hay que usar nombres
totalmente calificados (`UnityEditor.AssetDatabase.Refresh()`).
